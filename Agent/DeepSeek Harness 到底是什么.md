# DeepSeek Harness 到底是什么？一次说清这只"黑色鲸鱼"的真实身份

2026 年 8 月 13 日深夜，DeepSeek 悄悄扔出一个开源项目，社区管它叫"黑色鲸鱼"——这就是 **DeepSeek Harness**（简称 DSH）。不到 12 小时 GitHub Star 突破 5 万，48 小时突破 10 万，到第五天这个数字已经飙到了 14.9 万。

但热闹归热闹，很多开发者至今没搞明白：Harness 到底是个模型？是个评测工具？还是个 Agent 框架？本文基于公开资料，把它一次讲透。

## 一句话定性：它是"让模型干活"的执行底座

DeepSeek 官方给了一个干脆的等式：

> **Model + Harness = Agent**

模型是"大脑"，负责思考和推理；Harness 是"手脚和神经系统"，负责让模型真正动手干活——读文件、调工具、执行命令、跑测试、编排多步任务。

所以必须先澄清一个常见误解：**DeepSeek Harness 不是大模型，也不是大模型评测框架，而是一套开源的 Agent Harness（智能体运行框架）**。在 AI 工程语境里，"Evaluation Harness"确实常指评测框架（如 EleutherAI 的 lm-evaluation-harness），但 DeepSeek 这次发布的 Harness，定位是**智能体执行层**——承接"如何让模型持续完成任务"的环节，使模型能力由单次响应进一步延伸至可执行、可记录和可复用的工作流程。

这也是 DeepSeek 由模型 API 厂商走向实际工作交付层的标志性一步。

## 核心架构："一切皆插件"

Harness 最核心的设计理念只有五个字：**一切皆插件（Everything is a Plugin）**。

过去的 Agent 框架像一栋固定浇筑的大楼——核心是固定的，用户只能在边缘加插件。DeepSeek Harness 把这栋大楼拆成了一盒乐高。**模型适配器、工具注册表、会话日志、Agent Loop（整个运行循环）、沙箱、存储、调度、甚至 Web UI 界面本身，全部可插拔**。

官方有句很硬核的话："不存在需要打补丁的特权内核"。换句话说，你不用 fork 官方代码仓库去改核心逻辑，所有扩展都通过插件机制完成——扩展 DSH 的方式，就是把插件挂载到其他插件旁边。

支撑这套架构的底层，是一个叫 **Cordis** 的元框架，来自 DeepSeek 与北京大学联合发表的论文《A Programming Paradigm for Spatiotemporal Composability》。Cordis 负责插件的加载、卸载和依赖管理，不同插件通过服务与事件机制协同工作。

## 四种运行模式，丰俭由人

DSH 内置了四种运行模式，覆盖从直接使用到深度开发的不同需求：

- **标准模式**：完整工具组合，日常使用，支持文件编辑、命令行操作、检索、Skills、计划、子 Agent 和工作流
- **PTC 模式**：Programmatic Tool Calling，模型生成代码组合多轮工具调用，处理更复杂的 Agent 执行流程
- **极简模式**：仅保留 Shell 和文件编辑工具，用于模型基准测试
- **创造模式**：允许检查当前运行时，在内存中试验新插件和组合

除了支持 DeepSeek 模型外，Harness 也可配置 Anthropic、OpenAI 等模型提供方，并允许企业通过自定义兼容端点连接内部网关或自建模型服务，**兼容近 40 种模型**。

在工程可靠性上，DSH 采用**仅追加的会话日志**，把系统提示词、模型推理、工具调用、子 Agent 调度和上下文注入等信息全部永久记录，支持恢复、分叉、检索与回放。同时提供沙箱隔离，限制高危命令和文件越权访问。

整个项目以 **MIT 协议开源**，安装只需一行：

```bash
npx @deepseek-ai/dsh web
```

浏览器打开 http://127.0.0.1:3080，配置 API Key，选个工作区，开工。

## 它和 Claude Code 的根本区别

很多人拿 DSH 和 Claude Code 对标，但两者定位截然不同：

- **Claude Code 是"成品工具"**——装完就能用，但墙不能拆、格局不能动
- **DSH 是"开发者底层工具"**——不打算给你一个一键可用的终端助手，而是把施工图和所有预制件都开源了，告诉你"墙随便拆，零件随便换"

打个比方：别人把 Agent 做成精装房卖给你，DSH 把"造 Agent 的能力"开源给你。这也是为什么社区有人称之为 **"Agent 领域的 Linux 时刻"** 或 **"Agent 界的 Android"**。

> 💡 选型建议：如果你追求开箱即用、不想折腾底层配置，Claude Code 或 Codex 可能更适合你；如果你是喜欢折腾、想要掌控每一个环节的开发者，DSH 可能是你一直在等的东西。

## 真实性能：中上能力、低成本、较高耗时

光看架构不够，我们看看实际表现。上海人工智能实验室司南评测体系围绕 DeepSeek Harness 开展了综合性能评测，通过 **60 项真实环境长程智能体任务**，从 Score（任务完成能力）、Cost（调用成本）、Time（执行耗时）三个维度对 DeepSeek V4 Pro + DeepSeek Harness 组合进行了系统分析：

**📊 核心数据一览**

- **综合得分 45.0**，在 7 个价格相对稳定的 DeepSeek Harness 配置中排名第 3，位于 GPT-5.4 + DeepSeek Harness（53.8 分）与 GLM 5、Qwen3.5 397B + DeepSeek Harness（39.2 分）之间
- 与同模型 OpenClaw 相比：**成本下降 50%，耗时仅增加约 4.2%**
- 按 60 项任务估算，模型调用总成本约 **6 美元**，相比 OpenClaw 节省约 6 美元
- 单位成本得分由约 218.5 分/美元提升至约 **450.0 分/美元，提升约 106%**
- 顺序执行总耗时约 **630 分钟**

跨模型适配方面，Harness 的效果呈现明显的**模型依赖性**：

- **GPT-5.4 + DSH**：得分 53.8 位列第 2，同时成本最低、速度最快（平均耗时 3.98 分钟），是五种 Harness 中最快结果，最具代表性的优势配置
- **DeepSeek V4 Pro + DSH**：得分和成本优于同模型 OpenClaw，适合成本敏感、允许异步或批量执行的智能体任务，但执行耗时偏长
- **Qwen3.5 397B + DSH**：相较 OpenClaw 三项指标同时改善，适配协同效应强
- **GLM 5 + DSH**：当前版本下得分、成本和耗时均缺少明显优势，是适配优化的重点对象

总体来看，DeepSeek V4 Pro + DeepSeek Harness 当前属于 **"中上能力、低成本、较高耗时"** 的智能体配置。它在成本端优势突出，但 10.50 分钟的平均耗时对于交互时延要求高的场景仍需优化。

## 生态起点：5100+ 插件只是开始

截至发布第五天，DSH 已经累积了**超过 5100 个插件与超过 3500 位作者**，第三方社区项目已覆盖图像理解、长期记忆、飞书接入、Token 成本统计、桌面客户端和插件管理等方向。Python SDK 还可将同一套执行能力嵌入自动化程序和内部业务系统。

官方单独开了微信公众号"DeepSeek Harness 团队"，用黑色鲸鱼作标识，与模型产品的蓝色鲸鱼刻意区隔——这是要把它当独立生态经营的明确信号。

## 写在最后：Harness 工程化的产业信号

DeepSeek Harness 的发布，背后是 DeepSeek 由轻转重的产业路径。2026 年 6 月，DeepSeek 旗下 Harness 负责人崔添翼在社交媒体发起直聘，新成立的 DeepSeek Harness 组目标远大、工作繁重，仍然非常缺人——这侧面印证了 Agent 执行层在工程上的复杂度。

**对开发者的实际意义有三层**：

1. **对个人开发者**：可以用"乐高式"的插件组合，低成本搭建自己的专属 Agent 工具链
2. **对企业**：可以把内部数据接口、业务规则和工作流程封装为专属插件模块，在通用框架上组合专用能力
3. **对产业**：Agent 的建设方式有望由"从头开发完整系统"转向"在通用框架上组合专用插件"，为插件开发商、企业软件厂商、系统集成商及垂直应用公司带来新的产品与服务空间

回到那个公式——**Model + Harness = Agent**。当模型能力趋于同质化，Harness 这一层"手脚和神经系统"的优劣，将越来越决定一个 Agent 产品能不能真正干活、能不能规模化落地。DeepSeek 这次开源的不仅是一套框架，更是把"Agent 该怎么搭"的话语权，交还到了开发者手里。

至于它能否真正成为"Agent 领域的 Linux 时刻"，取决于两件事：一是 Cordis 插件架构能否经受住大规模生产环境的考验，二是社区插件生态能否持续繁荣。从发布五天 14.9 万 Star、5100+ 插件的开局来看，**这个故事才刚刚开始**。
