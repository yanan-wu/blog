# Claude Tag：当大模型从"对话工具"进化为"团队同事"

2026年6月23日，Anthropic发布了一项看似简单却意义深远的功能——Claude Tag。在Slack里@Claude，就能像委派任务给一位真实同事那样，把工作交给它。Anthropic官方明确表示，Claude Tag是"Claude Code演进的开端"，让它更主动，也更适配整个团队的协作方式。

表面上看，这只是把一个AI助手塞进了Slack频道。但站在大模型发展的前沿视角，Claude Tag的发布标志着一个重要转折：**大模型应用的重心，正从"单用户的对话工具"转向"团队级的、带有身份与记忆的智能体同事"**。要理解这一事件的分量，我们需要穿透功能表象，看清它在大模型产品演进坐标中的真实位置。



## 一、Claude Tag是什么：不是聊天机器人，而是团队成员

传统的"Claude in Slack"是一个聊天机器人：你在DM里问它，它回答你；上下文局限于那一条对话线。Claude Tag彻底重构了这个模型。

在Claude Tag的设计中：

- **共享身份**：在某个Slack频道里，只有一个Claude与所有人交互。任何人都能看到它正在做什么，也能从上一个人停下的地方接着推进对话。
- **持续记忆**：Claude会随着在频道中的参与，积累关于这项工作的上下文。用户不需要一遍遍地从头向它解释。
- **主动行动**：如果启用"环境行为（ambient behavior）"，Claude会主动向你更新它可能认为你需要知道的信息，标记来自其所处频道和所连接工具的相关信息，并跟进那些尚未解决、已陷入沉寂的对话或任务。
- **异步执行**：给它一个任务，你可以在它工作时专注于其他优先事项。它也可以为自己安排任务，在数小时或数天内自主推进一个项目。
- **Agent身份**：Claude在自己的身份下运行，管理员可以精细控制它能在哪些频道、调用哪些工具、访问哪些数据。每一次凭证使用都被记录，"Claude做了什么、谁要求的"永远有答案。

Anthropic在自己的产品团队中已经在广泛使用这一模式：**目前其产品团队65%的代码由内部版本的Claude Tag创建**。这个数据本身就说明了问题——它不是演示品，而是Anthropic自己每天都在用的生产方式。



## 二、第一层意义：打通Context的交互入口

大模型继续变强后，真正限制产品的不再是"智能（Intelligence）"，而是"上下文（Context）的完整程度"。

过去一年，业界在Context Engineering上投入了大量精力：人类先把上下文梳理清楚，再打包喂给模型。但这种方式有个天然瓶颈——**人类整理的上下文，永远只是原始信息的一个"摘要版本"**，细节、语气、决策背后的微妙考量，都会在整理过程中流失。

Claude Tag的思路是反过来的：**与其让人整理上下文再喂给模型，不如让模型直接"住"进原始的上下文里**。

Claude Tag工作在团队原本就在协作的Slack频道中，跨线程、跨天保留上下文——周一晨会讨论的内容，周四还在那里，不需要任何人重复。它还能在获得许可的情况下，自动从其他Slack频道和数据源学习。这意味着模型不再依赖人类事后的转述，而是直接沉浸在组织真实的信息流中。

这一层意义怎么强调都不为过。它实质上把大模型从"被喂养的消费者"变成了"在场的参与者"——这是Context层的一次质变。



## 三、第二层意义：真正的数字员工

如果说Context的打通是地基，那么Claude Tag的第二层意义就是：**它开始具备一个"数字员工"的核心特征——记忆、主动性、以及对完整项目负责的能力**。

传统AI工具是被动的：你问它答，你不问它不动。Claude Tag引入了"环境模式（ambient mode）"——它可以主动跟进频道里被冷落的讨论、标记需要决策的待办、在任务完成时主动通知你。

这听起来是个小功能，但范式含义巨大。一个真正的同事，不是因为你@他才工作，而是他会"盯"着工作本身。当AI开始主动识别"这件事需要被推进"并付诸行动时，**它和人类员工之间的界限就开始模糊了**。

更关键的是"负责完整项目"的能力。Claude Tag可以接受一个复杂任务，然后在数小时或数天内自主推进：拆解阶段、调用工具、遇到阻塞时主动求助、完成后汇报。这种"长时段、自治、对项目终态负责"的工作模式，正是我们对一个数字员工的期待。

Anthropic内部正在把这种模式推广到工程之外：**@Claude去追产品指标和数据、处理支持工单、甚至帮助查找棘手问题的根因**。当一个工具能够跨越工程、产品、运营、支持等多个职能边界工作时，它就已经不再是一个"功能"，而是一个"角色"。



## 四、第三层意义：AI Firm OS的雏形

虎嗅在一篇分析中指出，Claude Tag的第三层意义是**"AI Firm OS"——它开始成为公司的共享大脑，能把组织所有的经验和能力都沉淀下来**。Anthropic内部现在已经有了一些雏形。

这一层意义需要从组织演化的视角理解。

传统上，一个组织的"集体记忆"分散在：员工的脑子里、Slack历史消息里、文档系统中、Jira工单里、代码提交记录里。新员工入职要花数月才能吸收这些隐性知识。而Claude Tag的独特之处在于：

- **它在场**：它参与了组织的真实工作流，不是事后索引。
- **它跨边界**：一个频道里的Claude，可以在授权范围内从其他频道和数据源学习。
- **它持续积累**：记忆跨线程、跨天保留，不会因为对话结束而清零。
- **它可被治理**：管理员按频道维度划定Claude的访问范围，销售频道里的Claude不会把上下文泄露给工程频道。

当这四个特性叠加，Claude Tag就不再是"一个工具"，而是**组织记忆的活的载体**。它沉淀的不仅是信息，更是"这个组织如何思考、如何做决策、谁负责什么"的隐性知识。随着时间推移，它将成为企业最不可替代的资产——因为离开它，组织就失去了记忆的连续性。

这就是为什么Anthropic把Claude Tag称为"Claude Code演进的开端"，而不是"Claude in Slack的替代品"。它的野心不止于Slack，而是要在"团队日常工作的许多其他地方"都能@Claude——也就是说，Claude Tag是一种产品形态的探索，一种足够宽的产品容器，确保产品可以持续吃到模型进化的红利。



## 五、技术治理：Agent Identity带来的安全模型革新

Claude Tag的另一个前沿意义，在于它推动了一种**为自主智能体量身打造的安全模型**。

传统上，我们把AI接入企业系统时，要么借用个人账号（难以审计），要么用一个共享服务账号（权限难以精细化）。Claude Tag引入了"Agent Identity"概念：Claude在自己的身份下运行，管理员可以：

- 按频道配置Claude能访问哪些工具和数据
- 把敏感的链接器限制在单一私有频道中
- 随时从管理控制台调整权限
- 审计每一次凭证使用

这套机制回答了企业采用自主智能体时最焦虑的问题：**"Claude做了什么、谁要求它做的"永远有答案**。

这是大模型从"个人生产力工具"走向"企业基础设施"必须跨越的治理门槛。Claude Tag在这个方向上的探索，为大模型在受监管行业（金融、医疗、政务）的落地提供了可参考的范本。



## 六、结语：大模型应用的下一次浪潮

回望大模型应用的演进路径：

- **第一阶段**：ChatGPT式单用户对话。智能存在于模型里，但工作是孤立的、一次性的。
- **第二阶段**：Claude Code式个人智能体。AI能调用工具、执行多步任务，但主要服务于单个开发者。
- **第三阶段**：Claude Tag式团队智能体同事。AI成为团队的一员，共享上下文、持续记忆、主动行动、可被治理。

Claude Tag的发布，标志着我们正站在第二阶段的尾声和第三阶段的开端。它的真正意义不在于"Slack里能@Claude"这个交互形式，而在于它验证了这样一种可能性：**大模型可以成为组织的一个"角色"，而不仅仅是个人的"工具"**。

当AI能以一个成员的身份加入团队、积累记忆、主动推进工作、并对完整项目负责时，我们迎来的不只是效率的提升，更是**工作方式本身的重构**。Anthropic产品团队65%的代码由Claude Tag创建——这个数字预示着一个未来：在那个未来里，"@Claude"和"@同事"在语法上没有区别，在协作中没有隔阂。

这，就是Claude Tag的真正意义——**它不是把一个AI放进Slack，而是把AI请进了团队**。而这一步，距离AI成为组织的共享大脑，只剩下时间的距离。
